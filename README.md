# 电量日核算（Flask + SQLite）

电网数据员上传晚到的电表累计读数与换表记录，系统按计量点把相邻读数连成区间，
自动算出可核算的逐日用电量，并标记换表造成的缺口区间。

## 业务规则

- **读数 CSV**（表头 `point,ts,value`）：计量点、UTC 时刻（ISO 8601，须带 `Z` 或 `+00:00`）、
  非负十进制千瓦时累计读数。
- **换表 CSV**（表头 `point,ts`）：计量点、UTC 换表时刻。
- **幂等**：同点同刻同值的原样重传自动跳过，不重复计数；
  同点同刻**不同值**（文件内或对比既有数据）→ 整批拒绝。
- **区间计量**：每个计量点按时刻连接相邻读数构成区间 `(t1, t2]`：
  - 区间内发生换表（`t1 < s <= t2`，**含后次读数时刻**）→ 标记缺口，不推算增量；
  - 否则增量 = 后次 − 前次，计入**后次读数所属 UTC 日**；
  - 增量为负（读数倒退）→ 整批拒绝。
- **晚到读数**插入后自动拆分旧区间，增量按新区间重新归属。
- **补录换表**后，原区间变为缺口，此前计入的增量自动撤销。
- **事务性**：一次上传的原始记录与其影响的日结果在同一事务内生效；
  任何校验失败整体回滚，保持旧数据；被拒批次留有审计记录。
- **并发一致性**：SQLite WAL 模式；上传用 `BEGIN IMMEDIATE` 串行化，
  查询在单个读事务内完成，页面只能看到同一版本的完整结果（页面右上角显示数据版本号）。

## 15 分钟尖峰

日用量会把尖峰平均掉，因此另按计量点和 UTC 日期给出当日最高的 15 分钟平均功率（kW）。

- **时段划分**：从 UTC 零点起每 15 分钟一段（半开区间 `[s, s+900s)`），每日 96 段。
- **电量分摊**：按时段与相邻读数区间 `(t1, t2]` 的重合时长比例分摊区间增量，
  再除以 0.25 小时得到 kW。区间可跨日，重合部分分别计入各自时段。
- **完整性要求**：只有整段都被“无换表”的读数区间覆盖时才参与比较；
  部分覆盖、落在换表缺口内、或整日没有区间覆盖时，该日没有可比较时段，
  页面/接口会说明具体原因（`status = none`）。
- **并列时段**：所有取得最高值的时段全部列出（`ties`），包括起点/终点与功率。
- **按 (计量点, UTC 日) 缓存**：查询命中有效缓存时直接复用，不重读原始读数/换表明细。
- **增量失效**：补传读数或换表成功后，只刷新受影响的日期。受影响日期由“被改动的
  相邻区间”推出，跨日区间涉及的每个日期都算在内；未受影响的已算日期继续复用。
  从未查询过的日期没有缓存，首次查询时按最新数据计算。
- **失败处理**：上传/重算失败整体回滚，原数据与原有峰值保持不变并提示失败原因。
- **版本一致**：受影响日期的重算与原始记录写入同一事务，且所有写缓存都在
  `BEGIN IMMEDIATE` 内完成，旧计算无法在后续查询中被读到。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
```

访问 http://localhost:8000 。数据持久化在命名卷 `meter-data`（容器内 `/data/app.db`）。

### 本地开发

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
python run.py                 # 默认 0.0.0.0:8000（waitress）
pytest tests/                 # 运行测试
```

环境变量：`APP_DATABASE`（SQLite 路径，默认 `./data/app.db`）、`PORT`（默认 8000）、
`SECRET_KEY`、`USE_WAITRESS=0` 可退回 Flask 内置服务器。

## 页面与接口

- `GET /` — 上传入口、查询入口、最近上传批次（含被拒原因）。
- `POST /upload/readings`、`POST /upload/swaps` — 表单上传 CSV（字段名 `file`）。
- `GET /usage?point=..&start=..&end=..` — 逐日用量表 + 缺口区间；日期缺省时取该点数据最近 31 天。
- `GET /api/usage?point=..&start=..&end=..` — 同口径 JSON（含数据版本号），便于核对与集成。
- `GET /peak?point=..&day=..` — 指定 UTC 日的 15 分钟尖峰与并列时段页面；
  日期缺省时取最后一个读数区间覆盖的 UTC 日。
- `GET /api/peak?point=..&day=..` — 同口径 JSON：`status`（`ok` / `none`）、`peak_kw`、
  `ties`（并列时段）、`reason`（无可比较时段时的原因）与数据版本号。

## 实现说明

- 读数以文本存十进制（`Decimal` 计算），时刻规范化为定宽 UTC 字符串（字典序即时间序）。
- 日用量不做冗余物化：查询时在单事务内由原始记录现算，
  因此“原始记录”和“受影响日结果”天然同事务生效，晚到读数/补录换表的影响即时可见。
- 15 分钟尖峰反过来按 (计量点, UTC 日) 物化在 `daily_peaks`：尖峰计算要逐时段扫描，
  且同一日期会被反复查询；上传事务内只刷新受影响日期，其余行继续复用。
  峰值用 `Fraction` 精确计算，输出时再转十进制文本，避免浮点误差。
- 代码结构：`app/logic.py`（解析、校验、区间/日用量/尖峰计算）、`app/routes.py`（页面与 API）、
  `app/db.py`（连接与建表）、`tests/test_app.py`（规则、缓存失效与并发测试）。
